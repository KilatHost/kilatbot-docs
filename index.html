KilatBot — AI agents you shape to your business

KilatBot is a workspace of private AI agents for Indonesian businesses. A business picks the job, gives the agent a name and a channel, and changes anything later. Agents answer customers, write daily reports, draft content, or handle everyday admin — in the browser and on Telegram. They remember the work and run schedules on their own. No servers, no API keys to start: Kilat AI is included, or bring your own model key.

Templates include: Shop Assistant, Social Media Planner, Operations Reporter, General Assistant, Coder.

Flash agents sleep and wake in Jakarta

KilatBot agents run as Flash in Jakarta. A Flash agent sleeps when idle and wakes on demand. A change reaches an awake agent at once; a sleeping agent gets it when it next wakes — and a change never wakes it. A new agent costs nothing until it wakes. Reads that need the agent (a file, its schedules) wake it and answer status: "waking" with a retry time.

MCP quickstart

KilatBot's MCP endpoint lets a compatible AI client inspect your workspace and request a limited set of actions. Endpoint: https://kilat.host/mcp, stateless Streamable HTTP. Every request carries Authorization: Bearer <token>. Use a client that supports remote Streamable HTTP with custom authorization headers.

1. Create a read-only token

  1. Sign in to KilatBot and open Account → MCP in the dashboard sidebar.
  2. Enter a client name, select Read only, leave Site publish and PocketBase management unchecked, and create the token.
  3. Save the one-time secret in a password manager or your client's secret store. Tokens expire after 30 days; revoke ones you no longer use.

Use a separate token per client, and start read-only even if you plan to manage services later.

2. Connect a client

Generic configuration (adapt the secret reference to your client's documented secret store — never paste a real token into a file):

{
  "mcpServers": {
    "kilat": {
      "type": "http",
      "url": "https://kilat.host/mcp",
      "headers": {
        "Authorization": "Bearer <client-specific secret reference>"
      }
    }
  }
}

Claude Code (.mcp.json in your project, token from its launch environment):

{
  "mcpServers": {
    "kilat": {
      "type": "http",
      "url": "https://kilat.host/mcp",
      "headers": { "Authorization": "Bearer ${KILAT_MCP_TOKEN}" }
    }
  }
}

Then run claude from the token-bearing shell and check with /mcp.

3. Check the connection without changing anything

Start with: “Use KilatBot to list my services. Do not change anything.” Verify list_apps returns your workspace's services (an empty list is valid), then use the integer app_id from that result with get_app. Read tools include list_templates, list_apps, and get_app; lifecycle actions (start_app, stop_app, restart_app) need a manage token.

Security: treat a token like a password. Never commit tokens, paste them into assistant chats, or enable logs that expose authorization headers. Revoke a leaked token immediately.
